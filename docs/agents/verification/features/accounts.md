# Accounts

`agent-proxy accounts` lists the accounts the daemon holds, with provider, label, email, plan, priority, and status, and says which account gets each pool's new sessions, as a table or `--json`. `agent-proxy accounts add claude` signs in a Claude account, and `agent-proxy accounts add codex` a Codex (ChatGPT) account, through a login the daemon runs: it opens the browser, or with `--no-browser` prints the sign-in URL and takes the callback URL the owner pastes. A Claude login's redirect returns to `http://localhost:54545/callback`, a Codex login's to `http://127.0.0.1:1455/auth/callback`; the daemon listens there only while a login waits. A Codex account's email, plan and ChatGPT account id come from the id_token OpenAI returns. A new account joins the bottom of its pool, labelled after its email unless `--label` names it; signing in to an account already held updates its credentials and keeps its priority and enabled setting, and its label unless `--label` gives a new one. `accounts set <account> [--label] [--priority]`, `accounts enable|disable <account>` and `accounts remove <account>` change or forget an account named by its label, its email, or the start of its id. Priority is a place in the pool: a move shifts the others, removing an account moves those below it up, and a disabled account keeps its place. Removing an account deletes its file at once; a request it is already serving finishes, and the next goes to the next account. The daemon keeps each account in its own 0600 file in `$XDG_DATA_HOME/agent-proxy/accounts/`, a 0700 directory. It refreshes each Claude account's tokens about an hour before they expire, and each Codex account's about a day before, whether or not anything uses the account; an account whose refresh is refused, or whose refresh outcome is lost, shows Needs sign-in until it is signed in to again.

## Sub-features

- `accounts-list` prints a table of provider, label, email, plan, priority, and status (Active, Needs sign-in, Disabled), then a line per pool: `New <Provider> sessions go to "<label>".` or `No <Provider> account can take new sessions: each one needs sign-in or is disabled.`; or says how to add the first account.
- `accounts-json` prints `{ "accounts": [...], "pools": [...] }`: each account with the same fields plus `id`, `providerAccountId`, `enabled`, `addedAt`, and `lastUsedAt`, and never credentials; each pool as `{ "provider", "newSessionsAccountId" }` (`null` when no account is Active).
- `accounts-add-browser` opens the browser at the provider's sign-in page (Claude's, or OpenAI's for `codex`) and finishes when the redirect reaches the daemon.
- `accounts-add-paste` (`--no-browser`) prints the sign-in URL and the redirect address, and takes a pasted callback URL; a rejected paste asks again.
- `accounts-add-result` reports `Added <Provider> account "<label>" (<email>, <plan>) at priority <n>.` or `Signed in again to <Provider> account "<label>" …; its credentials are updated.` A Codex plan reads `Free`, `Plus`, `Pro`, `Team`, `Business`, `Enterprise`, …, from the id_token's `chatgpt_plan_type`; the account is identified by its `chatgpt_account_id`.
- `accounts-add-codex` signs in with Codex's OAuth client (`app_EMoamEEZ73f0CkXaXp7hrann`) at `auth.openai.com`, redirect `http://127.0.0.1:1455/auth/callback`, the spike's scopes and `id_token_add_organizations=true`, `codex_cli_simplified_flow=true`, `originator=codex_cli_rs`.
- `accounts-login-cancel` cancels the login in the daemon on Ctrl-C and frees port 54545 (1455 for Codex); a login nobody finishes expires after 10 minutes, and one the provider does not answer within 30 seconds fails.
- `accounts-callback-page` answers the browser on `localhost:54545/callback` (or `127.0.0.1:1455/auth/callback`): a success page, or a 400 page naming the problem.
- `accounts-files` keeps one 0600 JSON file per account in a 0700 directory, replaced atomically; a temp file a crash left behind is removed when the daemon starts.
- `accounts-match` names an account by label or email (ignoring case) or an id prefix; a name that fits several fails with `"<name>" matches <n> accounts. …` and one line per candidate (id, provider, label, email); one that fits none fails with `No account matches "<name>". …`.
- `accounts-set` renames (`Renamed Claude account "<old>" (<email>) to "<new>".`) or moves (`Moved Claude account "<label>" (<email>) to priority <n>.`) an account; the others in its pool shift. A priority outside the pool fails with `The Claude pool has <n> accounts, so a priority is 1 to <n>.`; neither flag fails with `Nothing to change. Give --label, --priority, or both.`
- `accounts-disable` prints `Disabled Claude account "<label>" (<email>). It keeps priority <n>.`; new requests skip it. `accounts-enable` prints `Enabled Claude account "<label>" (<email>) at priority <n>.`; it serves again from that place.
- `accounts-remove` prints `Removed Claude account "<label>" (<email>) and its credentials.`, deletes its file, and moves the accounts below it up; a request already streaming on it completes, and the next request goes to the next account.
- `accounts-refresh` refreshes an account's tokens an hour (Claude) or a day (Codex) before they expire, disabled accounts included, one refresh per account at a time, and stores the new pair before using it, logging `"account tokens refreshed"`.
- `accounts-needs-sign-in` flags an account Needs sign-in, logging `"account needs sign-in"` with a `reason`, when the provider refuses its refresh (`The refresh was refused: …`), when a refresh gets no answer within 30 seconds, its connection drops after sending, or the provider answers it with a 5xx other than 503 (`The refresh's outcome is unknown, so it is not retried: …`), or when the daemon starts and finds a refresh a stopped daemon never finished (`A refresh started at … never recorded its outcome, so it is not retried.`). Such a refresh is never sent again; `accounts add <provider>` for that account clears the flag. A refresh that cannot reach the provider, or that it answers with 429 or 503, leaves the account Active (`"account tokens not refreshed; will retry"`) and is tried again 5 minutes later.
- `accounts-not-running` fails with the daemon-down hint and starts nothing.

## How to get to it (user POV)

- Run `agent-proxy accounts [--json]`.
- Run `agent-proxy accounts add claude|codex [--label <label>] [--no-browser]`, then sign in to Claude or ChatGPT in the browser, or paste the URL the browser was redirected to.
- Run `agent-proxy accounts set <account> [--label <label>] [--priority <n>]`, `agent-proxy accounts enable <account>`, `agent-proxy accounts disable <account>`, or `agent-proxy accounts remove <account>`.
- Send a proxy request (see [Claude proxy](./claude-proxy.md)) after disabling, enabling or removing an account, or while removing the one serving it.
- Press Ctrl-C while `accounts add` waits.
- The browser lands on `http://localhost:54545/callback?code=…&state=…` (Claude) or `http://127.0.0.1:1455/auth/callback?code=…&state=…` (Codex) after signing in.
- Read `$XDG_DATA_HOME/agent-proxy/accounts/` (account files) and the `"login started"`, `"login finished"`, `"account tokens refreshed"` and `"account needs sign-in"` lines of the daemon's `daemon.log`.
- Leave the daemon running while an account's token nears expiry, or stop or kill it mid-refresh and start it again.

## Driving it with verify

Preconditions:

- `verify doctor` is all `ok`.
- The daemon is running in the run: `verify cli -- daemon start` exits `0`.
- Nothing else listens on port 54545: `curl -s localhost:54545` fails to connect.

- **Not running.** Before `daemon start`, run `verify cli -- accounts`, `verify cli -- accounts add claude`, `verify cli -- accounts set Work --label Home`, `verify cli -- accounts enable Work`, `verify cli -- accounts disable Work`, and `verify cli -- accounts remove Work`. Each exits `1`; stderr contains ``The agent-proxy daemon is not running. Start it with `agent-proxy daemon start`.``
- **Empty.** Run `verify cli -- accounts`. Exit `0`; stdout is ``No accounts yet. Add one with `agent-proxy accounts add claude` or `agent-proxy accounts add codex`.`` Run `verify cli -- accounts --json`. Exit `0`; stdout is `{ "accounts": [], "pools": [] }` (pretty-printed).

## Gotchas

- `verify cli` has no stdin, so the paste path is driven through `verify shell` with a FIFO; keep the FIFO's writer open (`exec 3>`) or `accounts add` sees end of input.
- `accounts add claude` without `--no-browser` opens the machine's real browser at claude.com; do not run it unattended.
- `AGENT_PROXY_PROVIDER_ENDPOINTS` (a JSON object shaped like `{"claude":{"apiBaseUrl":…,"authorizeUrl":…,"tokenUrl":…,"profileUrl":…,"callbackPort":…},"codex":{"apiBaseUrl":…,"authorizeUrl":…,"tokenUrl":…,"callbackPort":…}}`, any field optional) points the daemon at other provider endpoints. Set it with `verify cli --env` on `daemon start` to drive a full sign-in against a fake provider through the built binary. It is for verification and tests only, not an owner setting; an invalid value stops the daemon from starting with a message naming the variable.
- A finished login contacts the real Claude token and profile endpoints. Only the owner's real sign-in reaches them; the drives above never send Claude a request.
- Port 54545 is fixed. A daemon outside the run that is waiting on a Claude login holds it, and the run's login then fails with `Could not listen on 127.0.0.1:54545`. Port 1455 is fixed too, and shared with Codex itself: a waiting `codex login`, or another daemon's Codex login, makes `accounts add codex` fail with `Could not listen on 127.0.0.1:1455`.
- The seeded ids `a1`, `a2`, `a3` all start with `a`, so `a` alone is ambiguous by design; any longer prefix of the hex ids the daemon generates works the same way.
- `accounts remove` does not ask for confirmation, and the credentials it deletes come back only through a fresh `accounts add`.
- The Seeded list's `expiresAt` of 2099 keeps the keeper away from the seeded junk tokens; a seed due within the hour is refreshed against the real `platform.claude.com` unless `AGENT_PROXY_PROVIDER_ENDPOINTS` names a fake `tokenUrl`, and the real one refuses it, flagging the account Needs sign-in.
- Seeded files must match the daemon's format exactly; a file that does not decode is skipped with a `"skipping an unreadable account file"` warning in `daemon.log`, not shown as an error.
- The log is written in batches about once a second; wait before reading the login lines.
